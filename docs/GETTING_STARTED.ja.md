# はじめての使い方

[README](../README.ja.md) · [English guide](GETTING_STARTED.md) · [導入・ビルド手順](DISTRIBUTION.md)

このアプリでは、元 MOD の文章を見ながら訳を入力し、別の翻訳 MOD を作ります。文章を自動で翻訳する機能ではありません。XML や Git を操作する必要はありません。

## 1. アプリを開く

### Linux ポータブル版

配布用 tar.gz、またはローカルでビルドした `dist/linux-current/RimWorldTranslationEditor/` の**フォルダー全体**を展開・配置します。フォルダー内の `RimWorldTranslationEditor` を開いてください。ファイル管理アプリが実行を許可しない場合は、プロパティで実行権限を有効にします。

ターミナルから開く場合:

```bash
cd /path/to/RimWorldTranslationEditor
chmod +x RimWorldTranslationEditor
./RimWorldTranslationEditor
```

`_internal/` を実行ファイルと一緒に保持してください。Linux は対応する glibc、画面を表示するデスクトップ、フォントが必要です。ビルド環境は同梱の `release-manifest.json` で確認できます。

### Windows ポータブル版の準備

Windows 用 ZIP が提供された場合は、右クリックして **すべて展開**し、フォルダー内の `RimWorldTranslationEditor.exe` を開きます。ZIP の中から直接起動せず、`_internal/` を含む全ファイルを保持してください。

公開ダウンロードページはありません。ローカルの `dist/windows-wine/` に Windows x64 EXE を含む `wine-preview.zip` を保存しています。Wine 上でビルドした補助検証用プレビューで、Windows 実機の起動・DPI は未確認です。通常の Windows 検証済みリリースとは区別してください。

### ソース版

ソースからの準備は [README](../README.ja.md#ソースから起動開発する場合)にあります。ポータブル版の利用者は Python・Git・VS Code を別途インストールする必要はありません。

初回のガイドは **ガイドをスキップ**で閉じられます。もう一度見るときは **ヘルプ → ガイドを表示**を選びます。英語のメニューにする場合は **ヘルプ → 設定・文字サイズ・ゲームの場所 → 画面の言語 → English**です。翻訳先の言語とは別の設定です。Qt 標準のボタンやファイルダイアログも画面の言語に従います。独自のダイアログや診断文の一部は、英語の画面でも日本語のまま表示されます。

## 2. 元 MOD と翻訳先を選ぶ

1. **ファイル → 新しい翻訳**、または **新しい翻訳を始める**を選びます。
2. **Steam Workshopから選ぶ**、または **PC内のフォルダーから選ぶ**を選びます。
3. Workshop の一覧は MOD 名・Workshop ID・作者・packageId で検索できます。画像と作者を確認して選びます。よく使う MOD は **お気に入りを切り替え**で登録し、**お気に入りだけ**で絞り込めます。
4. 翻訳したい言語を1つ以上チェックします。日本語だけでも、複数言語でも使えます。
5. **ゲーム版・有効 MOD の抽出設定**でゲーム版と有効 MOD を確認し、**この条件でスキャン**を選びます。
6. 保存先を確認し、**この場所で作成**を押します。別の場所なら **別の場所を選ぶ**で空のフォルダーを選びます。

通常は `Documents/RimWorldTranslations/<MOD名>-JP/`、複数言語なら `<MOD名>-Translations/` が候補になります。アプリを展開したフォルダー・元 MOD・ゲーム・Steam Workshop の中を作業の保存先にしないでください。

```text
アプリのフォルダー               アプリ更新で置き換える
翻訳プロジェクトのフォルダー     project.json・履歴・生成 mod/ を保管
RimWorld の Mods フォルダー      生成した翻訳 MOD の導入先
```

Steam の標準的な場所や追加ライブラリーは自動で探します。見つからない場合はローカルの元 MOD フォルダーを選べます。**ヘルプ → 設定・文字サイズ・ゲームの場所 → フォルダー**タブで、Steam Workshop・ゲームの Mods・追加の MOD フォルダー（複数可）を指定することもできます。空欄なら自動検出で、指定したフォルダーは読み取り専用です。元 MOD の選択と、前提 MOD の探索に使います。Workshop のダウンロードや購読の変更はアプリでは行いません。

ゲーム本体の場所を登録する場合は **ヘルプ → 設定・文字サイズ・ゲームの場所 → 抽出**タブに、`Data/Core/` とゲーム実行ファイルがある RimWorld フォルダーを1行に1つ入力します。`Mods/` や Workshop フォルダーではありません。ゲームの場所が分かると、C# フィールドの判定などにも利用できます。設定は **一般**（言語・配色・文字サイズ・自動保存の間隔・設定の書き出しと取り込み）、**フォルダー**、**抽出**（ゲーム版ライブラリ・キャッシュの場所と**キャッシュを消去…**）、**出力**（翻訳者名・ライセンス・翻訳先言語の既定、バックアップの世代数）の4つのタブに分かれています。キャッシュの消去で削除されるのは、エディターが作った `game-table`・`schema` フォルダーだけです。

抽出設定には、利用する RimWorld の版（例: 1.6）と有効 MOD を指定します。利用可能なゲームの MOD 設定を初期候補として読み取り、**ゲームの MOD 設定を読み込む**から別の `ModsConfig.xml` も選べます。`ModsConfig.xml` の場所は設定の**フォルダー**タブでも指定でき、空欄のときは通常の場所のほか、Linux では Steam の Proton 用の保存先も自動で探します。これは読み取りだけで、ゲームの MOD 有効化や設定の変更は行いません。条件が分からない場合は **有効 MOD が不明**を選びます。その場合、条件付き項目は警告を付けて除外します。

あとから **プロジェクト → ゲーム版・有効 MOD の抽出設定**で条件を変更すると、その条件で再スキャンし、同じキーの訳を引き継ぎます。有効な他 MOD の XML 定義も参照できる範囲で継承・パッチの判定に利用します。

元 MOD が複数のゲーム版を宣言している場合は、編集する版を切り替えられます。**プロジェクト → 版ごとの状態…**で版ごとの状態（準備できた／未抽出／ゲーム未登録／ロード規則が未検証）と、正式出力に含まれるかを確認します。**別の版へ訳を引き継ぐ…**は、同じキーの訳を別の版へコピーする前に一覧で確認できます（原文が違う項目や既存の訳を含めるかは選べます。確認済み・承認済みは引き継ぎません）。**版どうしを比べる…**は、版ごとに原文・訳・項目の違いを一覧にします。**版の操作 → 宣言版を試験出力**で作る試験用の出力は、プロジェクト内の `mod-test/` に置かれ、直近の結果は **プロジェクト → 前回の試験出力結果**で開けます。

スキャン中はファイル数と候補数が画面下に表示され、**スキャンを中止**で止められます。中止しても、開いている既存プロジェクトの訳は保持されます。

## 3. 訳を入力して保存する

一覧の項目を選ぶと、下に英語原文と翻訳欄が表示されます。原文は読み取り専用です。翻訳欄へ入力するか、一覧の訳文セルを直接編集します。

**翻訳先の言語**で編集する言語を切り替えられます。他の言語の訳は保持されます。**言語を追加・変更**で対象を変えると、書き出す MOD には選択中の言語だけが含まれます。除外した言語の作業データは保持しますが、以前に生成したその言語の XML は次の書き出しで取り除きます。

検索は原文・訳文・キー・元ファイルに対応します。状態フィルター（**QA エラーあり**を含む）、Def の種類、元ファイル、メモの印での絞り込みと、**未訳を探す**を使うと作業を進めやすくなります。担当者での絞り込みは画面にありません。表示を更新したい場合は **編集 → 表示条件を更新（Ctrl+F5）**を使います。

一覧の上の絞り込みの行にある **次の未訳**（Ctrl+J）・**次の要確認**（Ctrl+Shift+J）は、絞り込みを変えずに次の該当行へ移動します。**Ctrl+Shift+Return** は確認済みにして次の未訳・要確認へ進み、**Ctrl+K** は「後で見直す」の印を付け外しします。編集欄の右の**候補**タブには、同じ原文の訳・公式訳・前提 MOD の既存の訳・用語集の用語が並び、Ctrl+Shift+1〜3 で挿入できます。**メモ**タブでは、項目ごとのメモと印（後で見直す／質問・要相談／ゲーム内で確認／一旦完了）を付けられます。メモは翻訳には出力されません。編集欄の下には、原文の記号を入れるボタンと、短い欄の幅の目安が出ます。

サイドバーの進み具合には、全体に加えて**名前・説明**（アイテム名・説明など、プレイヤーが最初に目にする文章）だけの進み具合も表示されます。**プロジェクト → ファイルごとの担当者…**では、元ファイルごとに担当者名を記録できます。

### 保存と書き出し

- **ファイル → 保存して書き出す（Ctrl+S）**は、`project.json` を保存し、プロジェクト内の `mod/` を更新し、変更があればローカル履歴を記録します。
- 編集を止めてしばらく経つと、自動保存も同じ保存・書き出しを試みます。初期値は60秒で、**ヘルプ → 設定・文字サイズ・ゲームの場所 → 一般**の**自動保存の間隔**で10〜3600秒に変えるか、0（自動保存しない）にできます。終了前には Ctrl+S と画面の結果表示を確認してください。
- **翻訳 MOD を書き出す（Ctrl+E）**は、書き出す前に**書き出しの確認**を開きます。チェック結果と出力ファイルの増減（追加・変更・削除）を確認でき、エラーがあると**書き出す**を押せません。**品質チェックを開く**から問題の行へ移動できます。確認して書き出すと、ゲーム用ファイルを再生成して作業データも保存します。
- **出力フォルダーを開く**で、生成した翻訳 MOD のフォルダーを開きます。初期状態はプロジェクト内の `mod/`、複数の版を試験出力したプロジェクトでは `mod-test/` です。**プロジェクト → 出力先フォルダーを設定**で出力先をプロジェクトごとに変えた場合は、そのフォルダーを開きます。

出力先に選べないのは、元 MOD、Steam Workshop、ゲームの `Data`、設定で追加した MOD フォルダーと重なる場所、プロジェクトのフォルダーそのもの（またはそれを含む場所）です。ゲームの `Mods/` では、`Mods/` 自体や深い場所は選べず、直下の専用フォルダー（例: `Mods/MyTranslation`）だけ選べます。**既定に戻す**で元の場所に戻ります。

書き出しにエラーがあっても、先に保存された作業データは残ります。**作業データは保存済み。XML 更新には診断の修正が必要**と表示されたら、現在の `mod/` を最新の訳と見なさず、診断を直して再度保存します。エラーが別の言語名を示す場合はその翻訳先へ切り替えて確認します。**プロジェクト → 品質チェック…（Ctrl+Shift+K）**を使うと、エラー・原文が変わった行・表記や文体・未訳・確認済みなのにエラーの行がタブ別にまとまり、行をクリックするとその項目へ移動します。

未訳の項目は出力せず、ゲームでは元の文章に戻ります。全項目を訳してからでないと導入できないわけではありません。重複・旧項目・手動で除外した項目も出力しません。

## 4. 確認状態と診断を使う

| 状態 | 作業の意味 |
| --- | --- |
| 未訳／翻訳済み | 訳が入っているかを示します。 |
| 新しい項目 | 再スキャンで追加された項目などを絞り込めます。 |
| 原文変更 | 原文が変わりました。以前の訳を保持しているので、内容を見直します。 |
| 要確認 | 抽出の不確かさや翻訳の問題があります。詳細と診断を確認します。 |
| 確認済み／承認済み | 現在の言語で、利用者が確認したことを記録します。訳や原文が変わると確認・承認を取り消します。QA エラーが残る行は確認済みにできず、進み具合の確認済み件数にも数えません。 |
| 削除・旧項目 | 元にない項目です。訳は作業データに残りますが出力しません。 |
| 除外 | 利用者が出力から除外した項目です。除外は言語別ではなく項目全体に適用します。 |

原文と訳を確認して **編集 → 確認済みにする**、または **承認済みにする**を選びます。プレースホルダーやタグの崩れなど QA エラーが残っている行では、理由が表示されて確認済みにできません。直してからやり直します。確認や承認は、ゲーム表示の自動検証や公開許可を意味しません。通常は未承認でも、確認済みでなくても訳を出力できます。

**プロジェクト → 抽出と翻訳の診断**で問題を確認します。診断は平易な言葉で「何が起きたか」と「どうすればよいか」を表示し、元の開発者向けの文面は**技術的な詳細**を開くと読めます。該当項目を特定できる行はダブルクリックで移動できます。選択した診断の対処案も確認してください。

編集欄の**技術的な詳細**には、その行が**対象になった理由**（公式訳が同じ型・フィールドを訳している、属性がある、英語の Keyed カタログにある、など）も出ます。抽出が間違っていると思う行は、後述の除外や分類の変更で直せます。一覧の右端の列は、手動で除外した行に ⊘、メモの印がある行に ⚑、メモだけの行に ✎ を表示します（ツールチップに内容が出ます）。

- `{0}` や `{PAWN_nameDef}` は文章に差し込まれる値です。種類・個数をそのまま残します。
- `<color=red>...</color>` などの対応するタグと属性も残します。プレースホルダーの不一致や対応するタグのエラーは書き出しを止めます。
- 改行・空白・極端に短い訳・用語の不一致・同じ原文の訳の違いは確認用の警告です。意図した訳なら文脈に応じて判断します。
- 品質チェックの**表記・文体**タブには、全角と半角の混在、半角カナ、原文のままの訳、文末や文体（です・ます調とだ・である調）の不揃いが出ます。これも確認用の警告です。
- **編集 → 用語集 → 訳のぶれ**タブは、同じ英語が複数の訳になっている用語を一覧にします。訳をクリックするとその訳を使う項目へ順に移動し、**選んだ訳を用語集に登録**で採用できます。

詳細欄の `schema` は C# フィールド情報、`catalog` は既存翻訳カタログ、`heuristic` は推定に基づく候補です。根拠の種類は正しさの保証ではありません。独自の C# 処理やパッチ、他 MOD の条件に依存する文章は、抽出しきれないことがあります。

抽出ミスを見つけたら **編集 → この項目の除外を切り替える**、または **抽出の分類を変更**を使います。**翻訳キーを手動追加**は正確な RimWorld キーを把握している場合の補助機能です。根拠が不明なキーを推測して追加する必要はありません。

## 5. ゲームへ導入する

1. RimWorld を終了して、訳を保存し、診断を確認します。
2. **ゲーム → 翻訳 MOD を導入・更新**を選びます。
3. 自動検出されたゲームを選びます。見つからない場合はゲーム本体のフォルダーを指定します。
4. 表示された導入先・ファイル数・新規導入／更新の内容を確認して、問題なければ実行します。
5. RimWorld を起動し、MOD 画面で元 MOD・必要な依存 MOD・翻訳 MOD を有効にします。翻訳 MOD は元 MOD より後に読み込みます。
6. ゲームの言語を翻訳先に切り替え、訳した項目が表示される実際の画面で確認します。

アプリは生成翻訳だけをゲームのローカル `Mods/` にコピーします。元 MOD や通常の `ModsConfig.xml` を変更せず、MOD の有効化は利用者がゲーム内で行います。`ModsConfig.xml` は、設定で指定した場所または Proton の保存先から読み取るだけです。手動でコピーする場合も生成した `mod/` フォルダー全体を使います。

**ゲーム → 必要 MOD と読み込み順**は、利用可能な MOD と通常の MOD 設定を読み取り、不足や順序を診断します。設定を自動修正する機能ではありません。

**プロジェクト → 前提 MOD…**は、元 MOD が必要とする MOD を調べます。足りない MOD は名前・packageId・Workshop のリンクで一覧され、**足りない MOD をコピー**や**選んだ MOD の Workshop を開く**が使えます（購読はアプリでは行いません。packageId だけで Workshop ID が分からない場合は名前で検索します）。見つかった MOD には、場所・同梱の言語と、その MOD に依存する行数（親 Def・型・条件付きの内訳）も表示します。足りない前提 MOD があっても翻訳作業はできますが、その MOD に依存する行は正しく抽出できないことがあります。

### 導入済み翻訳を更新・復元する

訳を編集して保存しただけでは、ゲームにコピー済みの翻訳は変わりません。**翻訳 MOD を導入・更新**をもう一度実行します。同じ翻訳 packageId を持つ、このエディターの生成物だけを更新対象にします。

更新前の翻訳はゲームの `Mods/.rimworld-translator-backups/` 内へ保存され、完了画面にバックアップ先を表示します。戻したいときは **ゲーム → 導入済み翻訳を復元**で、`backup.json` と `mod/` があるバックアップフォルダーを選びます。内側の `mod/` ではありません。復元前の状態もバックアップします。

別の MOD や管理対象外のファイルがあるフォルダーは上書きしません。拒否された場合は、診断と導入先を確認し、既存ファイルを勝手に削除せず別に保管してください。

### 隔離したコピーでテストする

**ゲーム → 隔離コピーでゲームをテスト**は、ゲーム本体・元 MOD・必要な依存 MOD・翻訳 MOD をプロジェクト内へコピーします。通常の設定やセーブを使わず、現在の翻訳先の言語で起動して、約2分で終了します。コピー分の空き容量が必要です。画面下の中止ボタンでも終了できます。

結果はプロジェクトの `game-tests/<識別子>/` にある `runtime-report.json`、`Player.log`、`runtime-stdout.log` に保存します。起動・ログの成功と、訳を画面で確認したことは別です。この GUI 操作はスクリーンショットによる訳の自動確認を行いません。対象の画面を開いて利用者が確認してください。

開発時の証拠では、6個の実 MOD の翻訳が隔離 RimWorld 内の診断用 `Verse.Window` に表示されました。通常の装備画面やプレイ全般の表示検証ではありません。詳細な範囲は [README](../README.ja.md#抽出と検証の範囲)にあります。

## 6. 既存の翻訳を取り込む・一括編集する

### 取り込み

**ファイル → 既存の翻訳を取り込む（Ctrl+I）**で次のどちらかを選びます。

- XML／CSV／PO／unified diff（.diff／.patch）ファイル
- 翻訳 MOD または言語フォルダー

選択中の言語を増やす必要がある場合は、先に **言語を追加・変更**で追加します。フォルダー名や CSV／PO の言語情報を使い、言語情報のない XML は現在の翻訳先へ取り込みます。

適用前に変更前・変更後、競合、不明キーを確認できます。初期状態では異なる既存訳を保持し、空の取り込み訳は無視します。上書き候補をプレビューへ含める確認は初期状態で **いいえ**です。必要な場合だけ候補を含め、内容を確認して **変更を適用**を押します。取り込み元に異なる訳が重複したキーは自動で選びません。不明キーは既存項目へ勝手に追加しません。

**ファイル → CSV を書き出す**は選択中の全言語を、**PO を書き出す**は現在の言語を出力します。CSV の書き出しでは**詳しい列を付ける**を選ぶと、`source_file`・`status`・`previous_english`・`note` の列も出ます。PO にはメモ・以前の英文・要確認（fuzzy）の印を常に含めます。外部で編集する場合は CSV の `id/kind/group/key/english/language` や PO の `msgctxt/msgid` を保持し、`translation` 列（PO では `msgstr`）を編集して戻すと照合しやすくなります。CSV の取り込みは UTF-8 のほか Excel の Shift_JIS に対応し、区切りはカンマ・セミコロン・タブを自動で判別します。`status` が要確認系の行や PO の fuzzy は、取り込み後も要確認として扱います。

他の人が作った翻訳 MOD は、**ファイル → 他の翻訳 MOD と照らし合わせる…**で、訳が違う項目・自分だけ未訳の項目・相手が未訳の項目・この MOD にないキーを確認してから取り込めます。

### 差分ファイル（.diff／.patch）を取り込む

通常の unified diff 形式で、翻訳 XML の変更を取り込めます。**既存の翻訳を取り込む**で差分ファイルを選び、続いて差分の**基準 XML があるフォルダー**を指定します。基準のフォルダーは読み取り専用で、ファイルへパッチを当てたり元 XML を書き換えたりしません。

差分ヘッダーの相対パスと基準フォルダーを合わせてください。たとえば次のヘッダーなら、基準フォルダーは `Languages/` が入っている翻訳 MOD のルートです。

```diff
--- a/Languages/Japanese/DefInjected/ThingDef/Things.xml
+++ b/Languages/Japanese/DefInjected/ThingDef/Things.xml
```

この場合は `<基準フォルダー>/Languages/Japanese/DefInjected/ThingDef/Things.xml` の**変更前の内容**を使います。`Languages/Japanese/` を基準に選ぶとパスが合いません。通常の Git の `a/`・`b/` 接頭辞は扱いますが、任意の接頭辞を推測して取り除くことはしません。

差分からメモリー内で再構成した XML 全体を取り込み候補にするため、差分で変更していない非空の訳も、新たな候補や既存訳との競合に含まれることがあります。変更前・変更後をプレビューして判断してください。削除されたキーや空の訳は現在の作業データを消しません。

基準の文章・行位置・改行などが一致しない差分、安全でないパス、XML 以外のパス、バイナリーなどの未対応差分は警告に表示します。推測して適用せず、正しい変更前の基準フォルダーと通常の unified diff を用意してください。既存訳との競合は通常の取り込みと同様に保護し、上書き候補を含める場合も明示的に確認します。

### 用語集・翻訳候補・置換

- **編集 → 用語集**で英語と訳語を追加します。用語集はプロジェクト共通で、QA は現在の翻訳先へ照合します。多言語プロジェクトでは訳語がその言語に適するか確認してください。登録していなくても、訳済みの項目から集めた**用語候補**が候補タブに出ることがあり、**用語集へ**で登録できます。
- 項目を選んで **同じ原文の翻訳候補（Ctrl+M）**を開くと、同じプロジェクト・言語にある完全に同じ原文の既存訳から選べます。複数の違う訳があるときは訳ごとにまとめて表示します。保存のたびに、エラーのない訳が設定フォルダーの `translation-memory.json` にも覚えられ、別のプロジェクトで同じ原文を訳すときの候補に出ます。候補タブの**同じ原文すべてに適用**は、訳した行と同じ原文の未訳の行へまとめて入れます（すでに別の訳がある行は変更せず、一括変更として元に戻せます）。外部サービスへの問い合わせや自動翻訳は行いません。
- **一括置換（Ctrl+H）**は現在の言語の訳文を置換します。初期状態の **表示中の項目だけ**を使うと、検索とフィルターで範囲を絞れます。正規表現にも対応し、適用前にプレビューします。
- 取り込み・一括置換は **一括変更を元に戻す（Ctrl+Alt+Z）**、**一括変更をやり直す（Ctrl+Alt+Y）**で戻せます。通常の文字入力の Ctrl+Z とは別の操作です。アプリ終了・別プロジェクトの読み込み・再スキャン後には、この一括変更の操作履歴は引き継ぎません。

## 7. 元 MOD の更新・作業の復元・引っ越し

元 MOD が更新されたら **プロジェクト → 元 MOD を再スキャン（Ctrl+R）**を選びます。同じキーの訳は言語ごとに保持し、原文変更・新項目・旧項目を区別します。原文が変わった項目の確認・承認は取り消し、変更前の英語を詳細欄に表示します。複数の版を持つプロジェクトで、版どうしの訳をそろえたいときは、再スキャンではなく**別の版へ訳を引き継ぐ…**と**版どうしを比べる…**を使います。診断を確認して保存し、ゲームに導入済みなら **導入・更新**も行います。

**プロジェクト → 履歴と復元**で以前の保存を選び、**選択した履歴を復元**を押すと作業データを戻して `mod/` を再生成します。復元前にも現在の保存状態を履歴へ残します。元 MOD は変更しません。

Git がない場合でも新しい履歴は `.history/` に記録できます。以前の `.git/` の履歴を読みたい場合には Git が必要です。外部バックアップでは、`project.json` だけでなく隠しフォルダーの履歴を含む**プロジェクト全体**をコピーします。

元 MOD のパスは `project.json` に記録されます。プロジェクトだけを移動しても、元 MOD が同じ場所にあれば再スキャンできます。

別 PC などへ1つのファイルで渡したいときは、**ファイル → プロジェクトバンドルを書き出す…**で `.rwtbundle` を作ります。訳・確認状態・用語集・メモ・担当者・版が入り、生成済みの翻訳 MOD を含めるかは書き出し時に選びます。元 MOD のファイルと、この PC での元 MOD の場所は含まれません。受け取る側は **ファイル → プロジェクトバンドルを開く…**を選び、中身を確認してから、自分の PC にある**同じ packageId の元 MOD**とプロジェクトの保存先を選びます。保存先に `project.json` がすでにあるときは上書きせず、エラーにします。バンドルに含まれないのは Git・`.history/` の履歴です。

バンドルを使わず、別 PC で元 MOD の場所が変わった場合は、以前のプロジェクトを保管したまま、新しい元 MOD からプロジェクトを作り、保存済みの旧 `mod/` から翻訳を取り込みます。この方法では古い確認状態や履歴は新プロジェクトへ移りません。ゲームの場所の設定を変えても、既存プロジェクトの元 MOD パスは変更されません。

### アプリを更新する

1. 作業を保存し、翻訳プロジェクト全体をバックアップします。
2. 新しいアプリを別フォルダーへ展開します。作業データをアプリフォルダーへ移さないでください。
3. **プロジェクトを開く**または **ファイル → 最近のプロジェクト**から `project.json` を開きます。
4. 開く・編集・保存・書き出しを確認してから、以前のアプリフォルダーを置き換えます。翻訳プロジェクトはそのまま保持します。

現在のアプリは既存の `schema: 1` の日本語・多言語プロジェクトを開けます。プロジェクトを別の環境へ移すには、フォルダーごとコピーするほか、`.rwtbundle` を使う方法もあります。アプリ更新と元 MOD の再スキャンは別の操作です。

更新通知を使う場合は、設定で実在する公開 GitHub の `owner/repository` と **無料の GitHub 公開リリースを確認する**を設定し、**ヘルプ → アップデートを確認**を実行します。初期状態では無効・公開先未設定です。定期確認はせず、アプリや作業データを自動で上書きしません。翻訳本文やプロジェクトのアップロードは行いません。

## 配布する前に

**プロジェクト → 配布用 MOD 情報**で名前・翻訳者・説明・翻訳ライセンスを入力し、保存して書き出します。配布する通常の対象は、生成した翻訳 MOD のフォルダー（既定は `mod/`、出力先を変えている場合はそのフォルダー）です。

Workshop に公開する場合の文章は、**ファイル → Workshop 用の文章を作る…**で用意できます。タイトル・説明（BBCode）・更新内容・公開前チェック・タグを `title.txt`・`description.bbcode.txt`・`changelog.txt`・`checklist.txt` として、選んだ別のフォルダーに保存します。更新内容には出力ファイルの増減を含められます。これは下書きの雛形で、エディターは Workshop へ公開しません。内容を確認して、公開は利用者が自分で行ってください。

元作者の画像を使わない場合は **元 MOD のプレビュー画像を使う**を外します。元画像を変更するのではなく、独自背景と国旗の Preview を生成します。元画像を使った派生画像、原文を含む作業データ・履歴、翻訳の公開には元作品の利用条件を確認してください。

国旗には MIT ライセンスの flag-icons を使っています。同梱ライブラリーの通知は [Third-party notices](../packaging/THIRD_PARTY_NOTICES.md)にあります。ゲーム・元 MOD はアプリ配布物に含めません。エディター本体の公開ライセンスはまだ選択されていません。

## 困ったとき

| 症状 | 確認すること |
| --- | --- |
| アプリが起動しない | アーカイブ全体を展開したか、`_internal/` があるかを確認します。Linux は実行権限と `release-manifest.json` の glibc を確認します。ターミナルから起動するとエラーを読み取れます。 |
| Workshop／ゲームが見つからない | ローカル元 MOD を選ぶか、設定にゲーム本体のパス（**抽出**タブ）を登録します。Workshop・Mods・追加の MOD フォルダーと `ModsConfig.xml` の場所は**フォルダー**タブで指定できます。 |
| 翻訳候補が0件 | 画像だけ・DLL だけの MOD、他 MOD を修正するパッチなどでは候補がない場合があります。診断を確認します。 |
| 書き出せない | エラーにある言語・キーのプレースホルダーとタグを直します。保存先が別の MOD や所有情報のないフォルダーでないか確認します。出力先を変えたいときは **プロジェクト → 出力先フォルダーを設定**で選び直すか、**既定に戻す**を使います。元 MOD・Workshop・ゲームの `Data`・追加した MOD フォルダーと重なる場所は拒否されます。 |
| ゲームが英語のまま | 最新の訳を保存後に導入したか、ゲームの言語、元 MOD と翻訳 MOD の有効化、読み込み順、診断を確認します。 |
| 元 MOD 更新後に表示がおかしい | ゲーム版と有効 MOD の抽出設定を確認し、再スキャンして原文変更を確認し、再保存・再導入します。抽出の推定にはゲーム内確認が必要です。 |
| 間違えて一括変更した | 一括変更を元に戻します。アプリを開き直した後なら履歴または外部バックアップから復元します。 |
| 元 MOD を移動して再スキャンできない | 元の場所へ戻すか、旧プロジェクトを残して新しいプロジェクトへ保存済み翻訳を取り込みます。 |

報告には **ヘルプ → 問題報告用の情報をコピー**で取得した情報、再現手順、期待した結果、実際の結果を添えます。コピーした情報には翻訳本文や元パスは含めません。個別のログや画像にはパスや文章が含まれることがあるため、添付内容を確認してください。

公開 Issues の URL はまだありません。作者へ報告するか、公開リポジトリーが用意された後に不具合・機能提案テンプレートを使ってください。
